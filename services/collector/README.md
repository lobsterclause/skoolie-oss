# @skoolie/collector

The thing that actually talks to your school district. It signs in to Home Access Center, parses five
pages, normalizes them into the schemas in [`@skoolie/shared`](../../packages/shared/README.md), works
out what changed since last time, and writes the result to Firestore in one batch.

Plain HTTP and [cheerio](https://cheerio.js.org/) — no browser, no Playwright, no headless Chrome. A
full run is a handful of GETs and finishes in a few seconds.

## Quick start

```bash
cp .env.example .env      # HAC_BASE_URL, HAC_USERNAME, HAC_PASSWORD, SKOOLIE_FAMILY_ID at minimum
pnpm exec tsx src/run.ts --adapter hac --dry-run
```

`--dry-run` prints the normalized snapshot as JSON and writes nothing anywhere. It doesn't need a
Firebase service account, so it's the safe way to find out whether the parser understands your
district before you commit to any of the rest.

## CLI

```
pnpm exec tsx src/run.ts [options]

  --adapter <name>    hac (default) | links | outlook | members
  --dry-run           print the result, write nothing to Firestore
  --dump              save the raw HTML to $SKOOLIE_DUMP_DIR — contains student PII, never commit
  --all-periods       fetch every marking period, not just the current one (slower)
  --student <id>      student document id (default: "primary")

  links / outlook only:
  --eml <file>        parse a saved .eml instead of, or as well as, the mailbox (repeatable)
  --graph-login       one-time Microsoft device-code sign-in; caches a token, then exit
  --limit <n>         (outlook) classify at most n messages this run
```

Every run drains `families/<id>.pendingMembers` first, whatever the adapter — that's how someone you
seeded before their first sign-in gets provisioned. `--adapter members` does only that.

Exit code is 0 on success, 1 on failure, and a failed run still writes its `runs/<runId>` document so
the dashboard can go red about it.

## How a run works

```
  login (or reuse the cached session cookie)
    │
    ├─ GET Registration.aspx      → parseRegistration  → student name, grade, school, counselor
    ├─ GET Classes.aspx           → parseClasses       → schedule, teachers, rooms
    ├─ GET Assignments.aspx       → parseAssignments   → per-course blocks + averages
    │     └─ (--all-periods: postback per marking period)
    ├─ GET Attendance/MonthlyView → parseAttendance    → this month, then the previous month
    └─ GET TestScores.aspx        → parseTestScores    → standardized-test history
    │
    ▼
  normalizeHac()          raw rows → Course / Assignment / AttendanceDay / TestScore
    │                     stable ids, status inference, score parsing
    ▼
  HacSnapshot.parse()     zod. A malformed snapshot fails here, before touching Firestore.
    │
    ▼
  diffAssignments() + diffCourses()      previous state vs. this snapshot → ChangeEvent[]
    │                                    pure functions, property-tested
    ▼
  writeHacSnapshot()      one batched write: documents + change events + the run doc
```

**Where the interesting logic lives**

| File | Responsibility |
|---|---|
| `src/adapters/hac/client.ts` | Login (the ASP.NET viewstate postback), cookie persistence, redirect following, error-page detection, request pacing |
| `src/adapters/hac/parse.ts` | **HTML → raw rows.** All the district-specific selectors are here and nowhere else |
| `src/adapters/hac/normalize.ts` | Raw rows → schema shapes. Stable ids, `statusFor()`, score parsing |
| `src/diff/index.ts` | Previous state vs. new snapshot → `ChangeEvent[]`. Pure, no I/O |
| `src/sink/firestore.ts` | Batched writes, run documents |
| `src/config.ts` | The environment, validated by zod at startup, so a typo fails before a run starts |
| `src/scripts/` | One-off exploration scripts. Not part of a run; don't point them at a live server in a loop |

## Adapting it to your district

**Everything district-specific is in `parse.ts`.** If your HAC is skinned differently, that's the only
file you should need to touch.

### 1. See what your HAC actually returns

```bash
pnpm exec tsx src/run.ts --adapter hac --dry-run --dump
```

The dump directory now holds one timestamped HTML file per page. The run's `warnings` array names any
page that parsed to nothing.

### 2. Find what your district renamed

The parsers are already written defensively, so a lot of theming survives untouched:

- **Registration** reads stock ASP.NET control ids (`#plnMain_lblRegStudentName`, `#plnMain_lblGrade`,
  `#plnMain_lblBuildingName`). These are generated by HAC itself and are the least likely to differ.
- **Tables** are read by *column header name*, not position — `cell($, tds, map, "periods", "period")`
  looks up the header text, so a district that reorders or inserts columns still parses.
- **Header and data rows** try `tr.sg-asp-table-header-row` / `tr.sg-asp-table-data-row` first and
  fall back to structural detection (a row containing `<th>`, a row containing `<td>`), so a district
  that dropped the HAC stylesheet classes still parses.
- **Teacher emails** handle a plain `mailto:`, a Cloudflare-obfuscated `data-cfemail` attribute, and a
  `/cdn-cgi/l/email-protection#` href.

So the usual failure is a genuinely different element: a container class that changed, a heading
format `splitCourseHeading()` doesn't recognize, or a score cell using a code this district invented.

### 3. Fix the selector and pin it with a fixture

Add a **synthetic** fixture to `fixtures/hac/` that reproduces your district's markup — invented
student, invented teachers, invented school — and a test case beside the existing ones in
`parse.test.ts`. Then fix the selector.

```bash
pnpm test          # golden-fixture tests for every parser
```

The fixture is the valuable half of the contribution: it's what stops the next change from breaking
your district again. **Never commit a real dump** — see [CONTRIBUTING.md](../../CONTRIBUTING.md).

### 4. Things that are probably not the parser

- **Login fails.** `HAC_BASE_URL` should be scheme + host only, no path. If your district puts HAC
  somewhere other than `/HomeAccess`, `HAC_PATHS` in `client.ts` is where to change it.
- **Everything is empty and login "succeeded".** HAC often serves an error page with a 200. That's
  what `isHacErrorPage()` is for; if your district's error page looks different, teach it there.
- **Assignments are empty at the start of a marking period.** That's not a bug — there's genuinely
  nothing in the gradebook yet. The warning fires either way, which is the honest behavior.

## Writing a new adapter

Nothing outside `adapters/hac/` knows HAC exists. To add PowerSchool proper, Infinite Campus, Skyward
or anything else:

1. Add your source to the `Source` enum in `@skoolie/shared`.
2. Write `adapters/<name>/` that produces the same shapes — `Student`, `Course[]`, `Assignment[]`,
   `AttendanceDay[]`, `TestScore[]`. How you get them is entirely your business.
3. Add a branch in `run.ts`.

The diff, the Firestore sink, the security rules and the whole UI keep working, because they only ever
saw the schema. If you find yourself needing to change something downstream, that's worth an issue —
it probably means the schema has a HAC assumption baked into it that shouldn't be there.

## The mail adapters

Both are optional, both are read-only, and both are off unless you configure a mailbox.

**`--adapter links`** harvests teacher websites. HAC has no field for them and campus directories
rarely publish them, so it reads school mail instead: any message from a `SKOOLIE_SCHOOL_DOMAINS`
address, or one that names exactly one of the student's teachers, gets scanned for Google Sites,
Classroom, Schoology, Canvas and syllabus-doc links. Results merge onto `families/<id>.teacherLinks`,
where a manual entry always beats a harvested one.

**`--adapter outlook`** summarizes school mail into `families/<id>/messages`: a category, a ≤90-word
Markdown summary, action items with due dates, and a link to the student and course when the sender is
a known teacher. **Message bodies are never stored.** It's the only part of this project that calls a
model; without `CLAUDE_CODE_OAUTH_TOKEN` it stores a deterministic fallback summary and says so in the
run's warnings. `SKOOLIE_INBOX_MAX` bounds the model calls per run, and stored messages are never
re-classified.

Either can read from **Microsoft Graph** (delegated `Mail.Read`, device-code sign-in — for mailboxes
where password IMAP is disabled) or **IMAP** (any mailbox; Gmail wants an app password). Setup for
both is in [docs/runbook.md](../../docs/runbook.md#reading-school-mail-optional).

Work offline with saved mail:

```bash
pnpm exec tsx src/run.ts --adapter links --eml syllabus.eml --dry-run
pnpm exec tsx src/run.ts --adapter outlook --eml newsletter.eml --dry-run
```

## Configuration

Every variable is documented in [`.env.example`](.env.example) and validated by zod in `config.ts` at
startup — a typo fails immediately rather than halfway through a run. The ones you can't skip:

| Variable | Why |
|---|---|
| `SKOOLIE_FAMILY_ID` | The document id under `families/`. Any slug; one per household |
| `HAC_BASE_URL` | Your district's HAC origin. **No default** — it's district-specific |
| `HAC_USERNAME` / `HAC_PASSWORD` | Your own parent credentials |
| `GOOGLE_APPLICATION_CREDENTIALS` | Service-account JSON path. Not needed for `--dry-run` |
| `SKOOLIE_TZ` | The school's IANA timezone. Decides what "today" is — a late-evening run must not roll over |

## Being gentle with HAC

This is a district's production system. The collector:

- **reuses one login.** Cookies persist to `SKOOLIE_SESSION_FILE`; a run only re-authenticates when
  the session is actually dead. HAC degrades noticeably after a burst of fresh logins, and
  `run.counts.logins` is there so you can watch for it.
- **paces itself** with random 400–1800 ms gaps between requests.
- **fetches five pages.** `--all-periods` adds a postback per marking period, which is why it's off by
  default.

Every 30 minutes during school hours is plenty. If you're debugging a parser, work from a dump, not
from a loop against the live server.
